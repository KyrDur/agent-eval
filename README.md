# Agent Eval

**把一次 AI 客服实验，做成可以查看依据、复测和复盘的项目经历。**

Agent Eval 是面向 AI 产品入门者的实践工作台。以模拟电商客服为场景，完成知识准备、回答评测、问题排查、一次修改和前后比较，再把实际做过的过程整理成求职素材。

- [在线演示](https://www.test.softcue.xyz/)：演示环境，功能可能落后于当前源码。
- [新手说明](README-evaluation-guide.md)：已有回答怎么检查、评分标准怎么用。
- [原理图解页面](AgentEvalFrontend/public/evaluation-guide.html)：本地启动后打开 `/evaluation-guide.html`。

本文更新至 **2026-10-28**，包含本地 RAG 开发版的功能与使用说明。

> **版本状态**：本次同步的是文档。10 月 28 日 RAG 升级代码仍在本地，尚未推送至 GitHub 或部署到演示站；直接克隆当前仓库不能获得下文全部新功能。下文标为“本地开发版”的能力已在本地实现，研究效果与上线状态另行说明。仓库 CI 只运行检查和构建，更新文档不会自动部署。

## 适合谁

主要面向 18–24 岁、缺少项目经历，希望理解 AI 产品如何评测和迭代的求职者。工作台的用户是学习者，实验里模拟的客服服务电商购物者，这两个场景分别记录。

可以先看不需要模型 Key 的案例图解，再用自己的模型连接做真实实验。平台提供执行与记录能力；实验结果来自本次运行，不能直接当作商业效果或个人独立开发成果。

## 功能介绍

| 功能 | 可以做什么 |
| --- | --- |
| 准备知识与测试题 | 导入或编辑资料，保存知识版本；聊天试用，把对话变成待审核测试题，也可审核 AI 生成的资料与题目。本地开发版增加政策要点清单、原文核对与模拟政策实验包。 |
| 看结果 | 查看初测或复测，一次聚焦一道题，核对原问题、Agent 回答、判定理由和参考依据。失败、证据不足、未执行等状态单独展示。 |
| 试修改 | 原有五种改法在本地开发版扩展为四组十种。一次只改变一个变量；原题与方案并排，保存后再分别应用和复测。 |
| 看变化 | 对照原题检查改善、退化和未变，记录保留、继续修改或不采用的决定。条件不一致时保留不可比较的原因。 |
| 运行日志 | 按改写、检索、重排、回答和评分查看保存的输入、输出、候选片段、用量与错误；可复制日志，查看不会重跑模型。 |
| 检查这次评分 | 本地新版可从每题评分旁打开，自动带入本题材料，复制提问请 AI 分析原判是否合理；复制不运行评测，也不改原判。 |
| 检查 AI 打分（进阶） | 支持人工与 AI 对照、固定回答重评和外部日志。本地新版将这些工具集中到进阶入口，并增加 DeepEval 交叉检查。 |
| 新手图解 | 用示意图说明 RAG 评测原理，配有证据、修改、复测和取舍的案例。本地开发版增加 6 个 RAG 练习及对应迁移题；全部为明确构造的教学回放。 |
| CSV 导出 | 导出初测、复测和前后比较，保留本次全部题目、原始判定、人工复核和版本信息。 |
| 整理项目 | 自动把保存的操作与结果整理成提问，复制给常用 AI，生成简历要点、面试讲述和项目复盘。历史材料仍可查看和导出。 |

### 四组十种改法 · 本地开发版

| 分组 | 改法 | 什么时候试、改什么 |
| --- | --- | --- |
| 补资料 | 补充或修改知识库 | 必要政策缺失或过期时，保存有来源的新版本，再用原题复测。 |
| 改善查找 | 中文语义查找 | 资料在库里，但中文同义问法查不到时，只更换向量模型。可选 BGE 中文模型，保持其他条件一致。 |
| 改善查找 | 关键词与混合检索 | 型号、专有词或数字规则容易漏查时，比较向量、BM25 或两路融合。 |
| 改善查找 | 查询改写 | 调整查找用语，再用改写后的问题检索；检查有没有偏离原问题。 |
| 改善查找 | 调整候选池 | 改变先找来供排序、筛选的片段数量，例如 20 → 40；最后交给模型的条数保持不变。 |
| 改善查找 | 资料重排（Rerank） | 对已经找到的候选重新排序，再取前几条；不能找回候选里没有的资料。 |
| 改善查找 | 最终提供条数（Top K） | 改变最终交给模型的原始选中片段数量，例如 3 → 5；候选上限保持不变。 |
| 补全上下文 | 调整切块与边界 | 主规则、条件和例外被拆散时，预览不同切法，并用同一知识版本准备对照索引。 |
| 补全上下文 | 补全相邻片段或父章节 | 保留原始命中，从同版本原文补充周边条件；检查新增内容与长度代价。 |
| 改善回答 | 修改回答提示词 | 资料已经提供，回答仍漏条件或不会澄清时，调整怎样使用资料组织回答；保持评分标准不变。 |

**候选池与 Top K 的区别**：假设先找来 20 段，排序后只给模型看 3 段。候选池调到 40，是从更多资料中挑，仍只给 3 段；Top K 调到 5，是从原有候选中多给 2 段。没有重排或融合时，扩大候选池可能不改变最终结果；库里已经没有更多片段时也不会凭空增加资料。启用上下文补全后，还会另记追加的片段，不能把最终上下文总数直接当作 Top K。

**切块怎么试**：先对照原政策，检查同一规则的条件和例外是否被分开；再预览当前切法与拟用切法，准备对照索引；最后保存方案、应用、用原题复测。标题切块也可能把条款拆得更散，需要看实际片段和回答结果。

修改页的 **「复制提问给 AI」** 自动带上当前题目、原回答、判定、检索资料和拟改参数，请 AI 分析原理、是否适合及怎样复测。补充备注可选，无需先填写四段分析。

### 证据页要核对什么 · 本地开发版

页面先让用户确认“这道题答对时不能漏掉什么”，再检查这些要点有没有进入模型实际收到的资料。

1. 点击「打开本题核对清单」，对照本次运行的政策与参考答案，检查必要要点、适用条件、例外以及是否需要追问用户。
2. 不确定时保存草稿；核对后记录审核人及参考政策是否足够。修改另存题集，再重新初测，历史运行不会被改成“已审核”。
3. 查看实际提供的资料。如果政策在库里却没送到模型，可以比较查找、排序、截取或上下文补全；资料已提供仍答错，再检查回答与评分。

“必要事实”就是回答不能遗漏的政策要点。例如问退款超时，至少需要说明“正常到账期限”和“超过期限怎么办”。**2 / 2** 只表示当前清单列出的两条原文都被找到，不能证明清单没有漏项；**待审核** 表示仍需人核对要点、条件与例外。原文包含关系不等于政策适用、语义充分或回答正确。

进阶详情保留五个位置：**库内原文 → 索引片段 → 候选召回 → 选中片段 → 实际上下文**。它们帮助定位信息在哪一步没有出现；旧记录缺少的字段明确显示未知。

### 原文诊断与 DeepEval · 本地开发版

| 工具 | 用来做什么 | 调用与结果 |
| --- | --- | --- |
| 指定政策原文诊断 | 怀疑模型没看到关键政策时，由用户选完整原文，保持模型、提示词和评分，追加一次对照回答。 | 至多 2 次实际请求；诊断独立保存，不修改原回答或原评分，也不直接计作正式检索收益。 |
| DeepEval 交叉检查 | 对已保存回答与实际上下文追加 Faithfulness、Contextual Recall，辅助检查原评分的分歧。 | 使用当前连接的评分模型，设实际请求上限；参考答案未审核或版本不匹配时跳过 Contextual Recall。保留原业务评分，分歧仍需核对原文。 |

两者都需要本题已经成功保存客服回答。只做了检索时，页面引导先准备包含回答的新初测。查看、复制、读取已有记录不会调用模型；点击运行诊断或交叉检查才会追加请求。DeepEval 需要另装可选依赖，一次检查可能分多步调用，费用按实际用量记录，未知费用不写成零。

### 项目经历自动整理

「整理项目」以复制提问为主要入口：

1. 自动汇总当前实验已保存的初测、修改、应用、复测和比较记录。
2. 在提问中要求 AI 查阅牛客等网站的 AI 产品项目、第一手面经和岗位要求，列出实际参考链接。
3. 请 AI 根据本次事实写出简历项目经历、约两分钟面试讲述、项目复盘及追问回答。

提问在浏览器本地准备，不会自动发送给第三方或启动模型。是否能联网查找参考，取决于用户粘贴后使用的 AI。尚未复测、评分失败或没有商业数据的部分保留实际进度，不能改写成已经提升。

## 第一次使用

**准备 → 看结果 → 试修改 → 看变化 → 整理项目**

1. 在「新手入门」先了解资料如何被找到、交给 Agent，再由评分模型检查。
2. 在工作区设置填写提供商地址、模型和自己的 Key，测试连接。
3. 使用演示资料或保存自己的知识版本，审核测试题与参考答案。本地开发版还可载入 10 份模拟政策与 16 个待审核开发题族，核对政策要点后再运行。
4. 运行初测。只想检查查找时可先做检索；要判断回答或追加诊断，需要完成包含回答的初测。
5. 先核对答错题的政策要点与实际资料，再选一个改法，保存、应用、用原题复测；需要新索引时先完成准备，再检查改善和退化。
6. 在「整理项目」复制提问，让 AI 根据记录帮助表达实际做过的事。

对某道题的原判有疑问，直接点评分旁的「检查这次评分 → 复制提问给 AI」。不用查找记录或填写分类与操作人；提问自动附本题问题、回答、资料、原评分与当时细则。主流程到「整理项目」就可以结束，需要检查评分方法时再用侧栏底部「检查 AI 打分 · 进阶」。

**旧回答重新评分与 Agent 重新回答是两种实验**：改评分规则后分数变化，不能证明客服能力提高。AI 建议也不能冒充独立人工校准。

## 结果怎么看

例如 8 道题中，3 道通过、4 道不通过、1 道评分失败：有效判定覆盖是 `7 / 8`，有效判定中的通过率是 `3 / 7`。评分失败单列，不能算通过，也不能隐去后宣称整批效果。

检索命中、回答是否有依据、用户任务是否解决分别记录。模型判定可能出错，平台提供人工复核和校准流程；这些功能不代表已经完成真实人工校准。一次运行也不能证明稳定性或因果关系。

## 技术与目录

前端使用 **Vue 3 + Vite**，后端使用 **Python 3.12 + FastAPI**。默认采用本地 Chroma / ONNX `all-MiniLM-L6-v2` 语义向量（384 维、CPU）和字符窗口切块，保留明确选择的词汇检索对照，失败时不会静默切换。

本地开发版增加可选 `BAAI/bge-small-zh-v1.5`（512 维、CPU、固定权重版本）、标题条款切块、BM25、RRF 混合检索和相邻 / 父章节补全。**默认配置未改**。中文模型有额外下载、内存与查询延迟，不能把“可选择”理解为“已经证明更好”。

实验保存题目、知识、索引、配置和评分协议快照。后台评测提交与查询进度分开，刷新后可接回已知任务。模型 Key 保存在后端进程内存，实验 JSON 不保存 Key。

遇到断线时，页面保留本次任务，点击「读取这次评测」只查询进度，不会再次运行模型。即使提交成功的回复丢失，也会按原请求编号核对回执；只有服务器明确未找到回执时，才提供按原参数重试。刷新页面仍先选择「继续上次实验」，不会默认读取历史记录。

本地开发版的索引构建也提供后台进度、取消与回执恢复；失败不会替换旧索引。主机一次执行一个编码构建，不代表已经完成生产并发容量验证。

```text
AgentEval/                  后端、公开演示资料与测试
  experiments/app.py        FastAPI 入口
  experiments/              实验、日志评分、校准、材料和后台任务
  evaluation/               执行结果、评分和证据检查
AgentEvalFrontend/          Vue 前端、单元测试与浏览器流程定义
  public/                   可独立访问的新手图解
examples/langsmith/         公开电商演示数据
scripts/langsmith-eval.py   可选 LangSmith 评测入口
requirements-runtime.txt   产品运行依赖
Dockerfile                  后端镜像
```

历史 `LEGACY_README.md`、旧 API、Memory 和监控模块保留用于溯源，当前入口以本文为准。

RAG 本地开发版的后端集中在 `AgentEval/experiments/rag_*.py` 与 `bge_embeddings.py`，前端包含政策核对、证据路径和统一修改方案组件。具体交付、可选依赖与使用方式见 [RAG 升级交付说明](RAG-UPGRADE-DELIVERY-20261028.md)；这些源码尚未包含在本次文档同步中。

## 本地运行

以下命令启动仓库当前已有源码。要使用前述 RAG 本地开发版，还需取得相应升级源码；仅更新 README 不会增加功能。

需要 Python 3.12、Node.js 22 和 pnpm 10。从仓库根目录开始：

```sh
git clone https://github.com/KyrDur/agent-eval.git
cd agent-eval
```

终端一，启动后端：

```sh
cd AgentEval
python3.12 -m venv .venv
.venv/bin/python -m pip install -r ../requirements-runtime.txt
# 首次联网下载公开向量模型，之后使用本地缓存。
.venv/bin/python -c "from chromadb.utils.embedding_functions import ONNXMiniLM_L6_V2; ONNXMiniLM_L6_V2(preferred_providers=['CPUExecutionProvider'])(['model initialization'])"
.venv/bin/python -m uvicorn experiments.app:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

终端二，启动前端：

```sh
cd AgentEvalFrontend
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://127.0.0.1:5173`。前端 `/api` 代理至 `127.0.0.1:8000`，可通过 `AGENTEVAL_BACKEND_URL` 修改目标。

默认模式用于本机单用户开发，数据写入 `AgentEval/data/experiments/`，已被 Git 排除。保持一个后端 worker；重启后需重新配置模型 Key。连接、作答、改写、重排和评分可能产生模型调用，单纯查看和复制记录不会重跑。

### RAG 本地开发版的验证与边界

- 工程记录：Python 完整回归 565 项通过、38 项跳过；后续相关边界检查 14 项通过。前端单元测试 197 项通过，生产构建通过，新增 RAG 浏览器流程在真实测试后端通过。这些是本地工程记录，并非本次文档提交的 GitHub CI 结果。
- 检索观察：仅用 16 个待人工审核的模拟开发题族，中文模型改善了本次草稿召回，但查询更慢；结构切块有退化，混合检索也未显示稳定优势。相邻补全带回更多原文，同时增加上下文长度。详见 [实验记录与限制](RAG-UPGRADE-RESEARCH-20261028.md)。
- 尚待完成：政策与参考答案的人审、独立人工校准、真实模型回答对照、保留题验证、目标用户观察和生产容量验收。检索研究未调用商业回答模型，不能声称已经提升客服回答质量或用户学习效果。
- 本轮没有部署演示站；部分旧的全站检查仍有未解决项，详见交付说明。

## 公网部署

公开部署使用匿名独立工作区、HTTPS 和同源反向代理：

```sh
docker build -t agent-eval:latest .
docker volume create agent-eval-state
docker run -d --name agent-eval-backend \
  -p 127.0.0.1:8000:8000 \
  -v agent-eval-state:/state \
  -e AGENTEVAL_ANONYMOUS_WORKSPACES=1 \
  -e AGENTEVAL_WORKSPACE_DIR=/state/workspaces \
  -e AGENTEVAL_PUBLIC_ORIGIN=https://your-domain.example \
  -e AGENTEVAL_COOKIE_SECURE=1 \
  agent-eval:latest
```

`AGENTEVAL_PUBLIC_ORIGIN` 与公开站点一致。匿名工作区通过服务端 cookie 隔离，写请求检查来源。前端执行 `pnpm build` 后发布 `dist/`，反向代理将 `/api/` 去掉前缀转给后端，保留 Host、Origin 和 `X-Forwarded-Proto`。持久化 `/state`，不要让两个服务进程同时写同一组工作区。
